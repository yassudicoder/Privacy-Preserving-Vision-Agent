Build it

Privacy-preserving browser automation

The agent sees the button. It never sees the card.

Sightline is a browser extension that reads the page, removes the personal data on your own machine, and only then asks an AI what to do — then does it. Two independent checks refuse to send if either one fails.

The trade nobody agreed to

Every AI assistant that can do things in your browser works the same way: it takes a picture of your screen, or a copy of the page, and sends it to a company. That is how it knows what it is looking at.

Which means the bank balance, the medical form, the salary line, the Aadhaar number and the half-written message are all in the payload, because nobody wrote code to take them out. The assistant did not want them. It got them anyway.

Sightline is built the other way round. The page is read and stripped on your machine first. What crosses the boundary is a description of the controls — this is a button, this is a search box, this one is called “Pay now” — and not the contents of your life.

Privacy you have to take on trust is not privacy. It is a promise.

The line down the middle is the edge of your machine.

Try to get something past it.

Type anything into the left pane — your own text, or one of the examples. The right pane is exactly what would leave this machine. It updates as you type, and nothing you enter is sent anywhere: the detectors are running in your browser, on this page.

    00  and then, twice, before anything is sent
    
    
    Two checks stand between that pane and the socket
    

    
    
      
    
        
    first
    
        
    Is this the right shape?
    
        
    
          A fixed list of 15 permitted
          fields. Anything else — a key the pipeline does not produce, a
          screenshot that cannot prove its blackouts landed, a marker carrying a
          token from another session — stops the step.
        
    
      
    
      
    
        
    second
    
        
    Does it still contain anything?
    
        
    
          Every detector runs again over the outgoing text, at the same threshold
          that produced it. If the second pass finds what the first missed, the
          step stops there.
        
    
      
    
    
    

    
    
      Neither of them repairs anything, and both run for every
      destination — including the one that sends nothing at all. A gate that
      stripped the offending field and sent the rest would turn “we found a leak”
      into “we sent something”. What comes back is a single action, checked
      locally before anything happens, up to a ceiling of
      8 steps.
    
    
  
    

    




    
  
    
    
    Almost all of a step is the AI thinking
    
    
    
      Privacy is not what makes an agent slow. Here is a real step from the
      panel’s own timing breakdown — every on-device stage, then the round trip.
    
    

    
    
      capture21 ms
      redact8 ms
      cover the pixels34 ms
      execute12 ms
      the model, thinking940 ms
    
    
    
    
      on your device — 75 ms
      the round trip — 940 ms
    
    
    
    
      From one step of a real run. The four on-device slivers together are under
      eight percent of the wall clock. Screen capture warm is
      23–26 ms; the on-device model, when it
      is switched on, is 30.3 ms.
    
    
  
    

    




    
  
    
    
    Fail-closed, in both directions, with nothing repaired on the way through.
    
    
    It would rather do nothing
    
    
    
      Every one of these stops the step. None of them quietly sends a repaired
      version, and none of them falls back to a different AI — a failure that
      silently became “on-device” would mean the panel reporting a plan produced
      by an agent nobody chose.

    01  where the AI lives
    
    
    Four destinations. One boundary.
    
    
    
      This is the only place the answer differs for a person, a company and a
      government department — and it differs in where the model runs,
      never in what leaves your machine. Pick one and watch the payload.
    
    

    
    
      
      your device
      — nothing
    
    

    
    
      

      

      

      
    
    

    
    The boundary does not move when the destination does.
    

    
    
      
    
        
    The payload does not change. That is the whole design.
    
        
    
          The three networked options are three instances of one client. There is
          no per-destination transform, because a second code path is a second
          place for the redaction to be forgotten — and a test stands up three
          real servers and asserts they receive a
          byte-identical body for the same page, with the access
          token present on exactly one of the three and appearing in none of the
          bodies.
        
    
        
    
          The fourth performs no request at all, so it is covered by a different
          assertion: that nothing is written to a socket. It is selectable, never
          a fallback.

    02  for work that cannot leave the building
    
      
    Two ways to run it with no internet at all
    
      
    
        
    
          For classified and regulated work the question is not which vendor to
          trust. It is whether a network request exists. There are two answers
          here and both are real.
        
    
        
    
          Nothing leaves. The on-device option performs no
          request. The vision weights are packaged inside the extension, so the
          whole thing installs from a file on a machine that has never seen a
          network. What you give up is the model: the offline planner is a
          keyword heuristic, and multi-step work is out of its reach.
        
    
        
    
          Nothing leaves the building. Run open weights on your
          own GPU and point the extension at it. You get a real model, and the
          privacy pipeline is the same code that runs in every other
          configuration.
        
    
      
    
      
    
        The extension never names a model and contains no vendor endpoint. Which
        model answered comes back as a measurement stamped on the
        receipt, not as a setting baked into the build.
      
    
    
    

    
    
      
    your own server, on your own hardware
    

    # any OpenAI-compatible endpoint: vLLM, Ollama, llama.cpp
$ VLM_ENDPOINT=http://gpu-01.internal:8000/v1 \
  VLM_MODEL=qwen2.5vl:7b \
  AGENT_AUTH_TOKEN=$(openssl rand -hex 32) \
  npm run server

# build an extension that opens already pointed at it
$ AGENT_ORIGIN=https://agent.your-org.internal npm run build
    
      
    
        Two secrets, pointing opposite ways. One is what your
        server presents to the model. The other is what your server
        requires from the browser. Neither is ever in the extension,
        and neither is echoed on the health endpoint or in an error.

        Build it, load it, grant one site
        
    
        
      There is no store listing and no download button, so this page will not
      pretend there is one. It is three commands and a folder, and it opens
      on-device with nothing configured.
    
        

    
        

        $ git clone https://github.com/yassudicoder/Privacy-Preserving-Vision-Agent
$ npm install && npm run vendor:model
$ npm run build
        
      
        
        Then open chrome://extensions, switch on developer mode, and
        load .output/chrome-mv3/. Firefox works too, with
        npm run build:firefox.
      
        
    
        

    
        
      It has no access to any page until you grant one site, one time. That
      approval cannot be automated — the browser requires a real click, and the
      click stops counting the moment the code waits for anything. Reaching a
      site you never approved is not a policy here. It is impossible.
